# 이런 노래 없나? 🎧

## 1. 프로젝트 소개

- 문제와 사용자:
  듣고 싶은 노래의 제목이나 가수를 정확히 알지 못하더라도,
  사용자가 원하는 분위기, 상황, 장르, 가사 키워드 등을 입력하면
  조건에 가장 잘 맞는 K-POP 노래를 찾을 수 있도록 함.
  주요 사용자는 상황이나 취향에 맞는 새로운 노래를 찾고 싶은 음악 청취자임.

- ES로 검색할 문서 1건:
  K-POP 노래 1곡

- 이 주제를 선택한 이유:
  노래는 제목과 가수뿐만 아니라 장르, 발매연도, 분위기, 상황,
  가사 키워드 등 다양한 검색 조건을 가질 수 있어
  Elasticsearch의 전문 검색, 필터, 정렬, 집계 기능을 활용하기 적합함.
  또한 최종적으로 자연어 기반 AI Search까지 확장하기 좋은 주제라고 판단함.


## 2. 실행 순서

1. Docker 환경 시작:
   Docker Compose를 이용하여 Elasticsearch와 Kibana 실행

2. index와 mapping 생성:
   songs index를 생성하고
   제목, 가수, 장르, 분위기, 가사 키워드, BPM 등의 필드 타입 정의

3. 데이터 생성·Bulk 적재:
   K-POP 노래 데이터를 JSON 형태로 생성한 뒤
   Elasticsearch Bulk API를 이용하여 일괄 적재

4. 검색 요청 실행:
   제목·가수 검색뿐만 아니라
   분위기, 상황, 가사 키워드 등의 조건을 조합하여 검색하고
   filter, sort, fuzzy, multi_match 등을 테스트

5. Kibana Dashboard 확인:
   발매연도, 장르, 분위기, 가수 등의 데이터를 집계하여
   K-POP 데이터의 특징을 시각화


## 3. 데이터와 mapping

- 문서 수:
  약 500곡 예정

- 데이터 생성 규칙과 seed:
  동일한 데이터를 재현할 수 있도록 고정 seed를 사용하여 생성
  seed: 20260831

- 개인정보 미사용 확인:
  개인정보를 포함하지 않음.
  노래의 제목, 가수, 장르, 발매연도 등의 공개 음악 정보와
  프로젝트용으로 생성한 분위기·상황·가사 키워드 메타데이터만 사용함.
  저작권 문제가 발생할 수 있는 가사 전문은 저장하지 않음.

- 핵심 필드와 타입 선택 이유:

    - title: text
      → 노래 제목 전문 검색 및 fuzzy 검색을 위해 사용

    - artist: text + keyword
      → 가수명 검색과 가수별 집계를 모두 지원하기 위해 사용

    - genre: keyword
      → 정확한 장르 필터링 및 집계를 위해 사용

    - release_year: integer
      → 특정 연도 범위 검색 및 연도별 집계를 위해 사용

    - mood: keyword
      → 청량한, 몽환적인, 신나는 등의 분위기 필터링에 사용

    - situation: keyword
      → 드라이브, 운동, 여행, 새벽 등의 상황별 검색에 사용

    - lyrics_keywords: text
      → 사용자가 원하는 가사 관련 키워드를 검색하기 위해 사용

    - lyrics_theme: text
      → 짝사랑, 이별, 청춘, 위로 등의 가사 주제를 검색하기 위해 사용

    - bpm: integer
      → 빠른 곡, 느린 곡 등의 조건 검색 및 범위 필터에 사용

    - energy: integer
      → 곡의 에너지 정도를 1~10 단계로 표현하여 조건 검색에 사용


## 4. 검색·품질 테스트

| 검색 질문 | 기대 결과 | 실제 결과 | 판정 |
|---|---|---|---|
| 가사에 여름이나 바다가 등장하는 청량한 노래 | lyrics_keywords에 여름·바다가 있고 mood가 청량한 곡이 상위 검색됨 | 테스트 후 작성 | - |
| 새벽에 혼자 들을 몽환적인 여자 아이돌 노래 | 상황이 새벽이고 분위기가 몽환적인 여자 아이돌 곡이 검색됨 | 테스트 후 작성 | - |
| 제목을 `수퍼노바아`처럼 잘못 입력 | fuzzy 검색을 통해 유사한 실제 제목이 검색됨 | 테스트 후 작성 | - |


## 5. Dashboard

- Dashboard 사용자:
  음악 검색 서비스를 운영하거나 음악 데이터의 특징을 확인하려는 사용자

- 차트 1이 답하는 질문:
  연도별로 등록된 K-POP 노래 수는 어떻게 변화하는가?

- 차트 2가 답하는 질문:
  데이터에서 가장 많이 나타나는 분위기(mood)는 무엇인가?

- control/filter 목적:
  가수, 장르, 발매연도, 분위기 등을 선택하여
  조건에 따라 Dashboard의 전체 통계를 동적으로 확인할 수 있도록 함.


## 6. AI Search 확장 판단

- 적용 여부와 근거:
  적용함.

  기존 검색에서는 사용자가 장르, 분위기, 가사 키워드 등의
  조건을 직접 선택하거나 검색어로 입력해야 함.

  AI Search를 적용하면
  "여름밤에 바닷가를 걸으면서 듣고 싶은 청량하고 너무 시끄럽지 않은 노래"
  와 같이 사용자가 원하는 상황을 자연어로 입력해도
  검색 의도를 분석하여 관련된 분위기, 상황, 가사 주제 등을 기반으로
  적합한 노래를 검색하도록 확장할 수 있음.

  따라서 단순 키워드 검색보다 사용자의 추상적인 음악 취향과 상황을
  검색에 반영할 수 있다는 점에서 AI Search 적용 가치가 있다고 판단함.
